# ro-twin-streetview

로드뷰는 눈이다. 손으로 모델링하기 전 반드시 로드뷰에서 먼저 본다.

## URL 구조 (2026-10-23 확인)

```
https://map.naver.com/p?c=18.00,0,0,0,adh&p=<panoId>,<yaw>,<pitch>,<fov>,Float
```

- `panoId`: 22자 파노라마 ID. 예: 학교 정문 `DlPs12G8z5Yxtle6UuL7Ug`
- `yaw`: 수평 방향(도). `pitch`: 상하. `fov`: 화각(80 권장).
- `&isMini=true`를 빼면 전체화면 파노라마로 열린다.
- 첫 진입 시 온보딩 팝업이 뜨면 Esc가 아니라 X를 누른다 (Esc는 뷰어 전체를 닫는다).

## 이동

- 같은 URL에서 `p=`만 바꾸면 해당 파노라마로 점프한다.
- 이웃 파노라마: 파노라마 안의 이동 화살표를 클릭하면 URL의 panoId가 바뀐다.
  바뀐 panoId를 읽어서 순회 로그에 기록한다.
- 키보드: 방향키는 회전/이동에 쓸 수 있으나 Esc는 뷰어를 닫으므로 주의.

## 관찰 기록 규칙 (pano 1개당)

- 위치(도로명: 화면 좌하단 표기, 예: 강남1길), 촬영 월(날짜 선택기, 최신 우선)
- 건물: 층수, 정면 폭(차선 수로 추정), 외장재, 간판 문구(텍스트만), 옥탑 구조물
- 도로: 차선 수, 중앙선 종류, 보도 유무, 가로수/전봇대 간격
- **이미지를 저장·텍스처로 굽지 않는다.** 텍스트 관측 기록만 남긴다.
- 관측 1건 = Blocks 레코드 1건 추가 또는 `verified=true` 변경의 근거가 된다.

## 큐브맵 방위 보정 및 번지 밀림 방지 규칙 (2026-10-25 승격)

- 네이버 파노라마 타일은 4개 큐브 면(`[f, r, b, l]`, 각 90°×90°)으로 제공되며, `f`면 중심이 촬영 방위(`yaw`), `r`면이 `yaw+90°`, `b`면이 `yaw+180°`, `l`면이 `yaw+270°`이다.
- 선형 보간(`pano.py`)은 큐브 모서리(±45°) 부근에서 최대 35°의 방위 오차가 발생해 인접 번지(예: `88-15`, `88-17`, `88-21`)가 한 칸씩 밀려 판독되는 원인이 된다.
- **반드시 `scripts/pano2.py` (탄젠트 투영 보정)와 `data/tmp/pano_<id>_raw.png` 전체 시트 + `data/tmp/zone_<id>.txt` 거리/방위표를 함께 대조**하여 연속된 건물열의 순서(동↔서, 남↔북)와 층수·지붕 형태를 먼저 맞춘 뒤 간판 텍스트를 확정한다.
- 상업 간판이 없는 순수 주택/빌라는 억지로 가상 상호를 붙이지 않고 `noSign = true` (또는 실제 빌라 현판명)로 기록한다.
